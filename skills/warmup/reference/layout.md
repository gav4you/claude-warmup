# C:\DevTools layout and organization rules

```
C:\DevTools\
├─ README.md, catalog.json        generated by scripts\build-catalog.ps1 (name, category, path, source, version)
├─ 01-Go … 10-Editors-IDEs\       .lnk shortcuts: GUI → app; CLI → pwsh -NoExit showing the tool
├─ scoop\                          SCOOP root: apps\<name>\current (stable path), shims\ (on PATH), persist\
├─ gopath\                         GOPATH; bin\ = GOBIN; pkg\mod = module cache
├─ gocache\                        GOCACHE
├─ sdk\                            portable SDKs not in Scoop (flutter)
├─ fnm\                            FNM_DIR
├─ portable\                       portable non-dev apps
├─ _installers\                    verified offline installers worth keeping
└─ _scripts\                       catalog/reinstall/cleanup scripts, scoopfile.json (scoop export)
```

## Rules
- **Install Scoop at the root:** first run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`, then download `https://raw.githubusercontent.com/ScoopInstaller/Install/master/install.ps1` to a file, then run `install.ps1 -ScoopDir C:\DevTools\scoop -ScoopGlobalDir C:\DevTools\scoop-global -RunAsAdmin` (the flag is needed in an elevated shell). Add buckets: `extras`, `versions`, `java`.
- **Go:** `go env -w GOPATH=C:\DevTools\gopath GOBIN=C:\DevTools\gopath\bin GOCACHE=C:\DevTools\gocache`. Move an existing `%USERPROFILE%\go` with `Move-Item` (same-volume rename is instant), then `New-Item -ItemType Junction` back at the old path so hardcoded scripts keep working.
- **Migrating a tool from winget/MSI to Scoop:**
  1. `scoop install` it.
  2. Verify with `scoop export` (not captured console output).
  3. Uninstall the old copy (`winget uninstall --id <id> -e --purge`, or the product's own uninstaller).
  4. Remove its PATH entries, backing up PATH to a file first.
  5. Fix anything that referenced the old path (git credential helper, env vars, shortcuts).
- **Keep system-installed:** services (Docker, PostgreSQL, cloudflared), Git for Windows, system Node (MCP configs hardcode it), VS Code, Android Studio + SDK + NDK, VS Build Tools, the `py` launcher.
- **Before moving anything,** search for references: `~\.claude.json`, `~\.claude\settings*.json`, `~\.codex\config.toml`, `~\.gemini\settings.json`, VS Code settings, scheduled task actions, services (`Win32_Service.PathName`), user/machine env vars, Start Menu/Desktop `.lnk` targets, and `pyvenv.cfg` files (via `es wfn:pyvenv.cfg`).
- **After every change,** run `scripts/build-catalog.ps1`, `scoop export > _scripts\scoopfile.json`, and a dead-PATH-entry sweep.
- **Reports and handoffs** go wherever the user's CLAUDE.md says; otherwise ask. Never put them in the tool tree.
- **Swapping a toolchain installed by MSI** (Go at `C:\Program Files\Go`, Python 3.x MSI, Node MSI):
  - **Anytime (staging):** install the Scoop copy alongside it. It lands on user PATH, so the MSI on machine PATH keeps serving running loops. Check it runs via its full path.
  - **When idle only,** in this order:
    1. `go env -w` the new GOPATH/GOBIN/GOCACHE, and move the old dirs with a junction.
    2. Uninstall the MSI, which removes its machine PATH entry.
    3. `go install` the tools, and recreate venvs.
    4. Verify that `where.exe go` and `where.exe python` each give one result.
